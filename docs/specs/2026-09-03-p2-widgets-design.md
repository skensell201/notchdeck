# NotchDeck P2 — Widgets

**Date:** 2026-09-03
**Status:** Draft
**Parent spec:** [`2026-09-02-notchdeck-design.md`](2026-09-02-notchdeck-design.md)
**Depends on:** P1a (module registry, tab strip, `hasLiveContent` peek) and P1b (shelf), both merged.

P2 fills the tab strip out: clipboard history, a pomodoro timer, system stats, calendar, a Shortcuts launcher, and a camera mirror.

---

## 1. Scope

Six modules, all conforming to the `NotchModule` contract P1a established. Nothing in the shell changes; each module is a new file set plus one line of registration.

Split into two deliveries by the thing that actually separates them — whether macOS has to ask the user for permission:

- **P2a — Clipboard, Timer, Stats.** No permissions, no external processes. Most of the work is pure logic and is unit-tested.
- **P2b — Calendar, Shortcuts, Mirror.** Each needs either a TCC grant or a subprocess, and all three need a shared way to ask, explain, and degrade.

---

## 2. Shared: module ordering and idle cost

The registry already activates exactly one module at a time and deactivates the rest. P2 leans on that hard: the clipboard poller, the metrics sampler and the camera session must all start in `activate()` and stop in `deactivate()`, so a closed notch costs nothing.

The one exception is the timer, which keeps running while the panel is closed — that is the entire point of a timer — and reports `hasLiveContent` so the collapsed notch shows its countdown, exactly as the media module does for a playing track.

## 3. P2a modules

### 3.1 Clipboard

**Watching.** `NSPasteboard.general.changeCount` polled while the module is active. There is no notification for pasteboard changes; polling is the only mechanism, so the interval is a visible trade-off — 0.4 s is fast enough to feel instant and slow enough to be free.

**What is skipped, and why it matters.** A password manager marks its copies with `org.nspasteboard.ConcealedType`, and short-lived internal copies use `org.nspasteboard.TransientType` and `org.nspasteboard.AutoGeneratedType`. Storing those would turn the notch into a password log. Any pasteboard item carrying one of those types is ignored outright, and so is anything copied by an app on the user's exclusion list.

**What is kept.** Text, URLs, and images, newest first, de-duplicated by content so re-copying the same thing promotes it rather than adding a twin. A capacity cap evicts the oldest unpinned entry; pinned entries never evict.

**Persistence.** Text and URLs are written to Application Support. Images are kept in memory only — persisting them would grow without bound for little benefit, and the user who wants an image kept can pin it for the session or drop it on the shelf.

**Using an entry.** Clicking one writes it back to the pasteboard. NotchDeck does not synthesise ⌘V: that needs Accessibility, and the paste is one keystroke away anyway.

### 3.2 Timer

A pomodoro: work, short break, long break, repeating. The phase machine is a pure value type — start, pause, resume, skip, reset, and a `remaining(at:)` function — so every transition and boundary is tested without a clock.

Running state survives the panel closing, and drives `hasLiveContent` so the collapsed notch shows the countdown. Completion plays a system sound and moves to the next phase automatically; the notch peek is the notification, so no `UNUserNotificationCenter` and no permission prompt.

### 3.3 Stats

Battery (percentage, charging, time remaining), CPU load, memory pressure, and network throughput. Sampling runs only while the module is visible.

**A known limitation, measured rather than assumed.** Darwin's `getifaddrs` reports `if_data` byte counters as 32 bits, so they wrap roughly every 4 GiB — hours of ordinary use, not a theoretical edge. A counter that goes backwards is treated as a reset and throughput reports "unknown" for that one interval. The 64-bit alternative is `sysctl` with `NET_RT_IFLIST2` and `if_data64`; two seconds of a blank rate every few hours does not justify replacing a working sampler, so this stands until it annoys someone.

Every reading comes from a `MetricsSampling` protocol so the module and its formatting are tested against fixtures; the real implementation uses IOKit power sources, `host_statistics64`, and `getifaddrs` deltas. Throughput is a rate, so it needs two samples — the first sample after activation reports no rate rather than a wrong one.

## 4. P2b modules

### 4.1 Calendar

EventKit, full-access request. Today and the next few days, all-day events handled separately, and a join button when an event's notes or location contain a recognisable meeting URL. Without access, the module shows what it needs and a button that opens the right pane of System Settings.

### 4.2 Shortcuts

`shortcuts list` to enumerate, `shortcuts run <name>` to execute, both as subprocesses behind the same protocol seam the media adapter uses. Favourites are pinned to the front. No permission is needed to list or run.

### 4.3 Mirror

An `AVCaptureSession` preview of the front camera, started in `activate()` and torn down in `deactivate()` so the camera light is never on longer than the panel is open. Needs `NSCameraUsageDescription` in `Info.plist` — requesting authorization without it terminates the process, so the plist entry lands in the same commit as the code.

### 4.4 Shared permission handling

One small `Permissions` piece: a status enum, a request entry point per capability, and a reusable empty-state view that explains what the module needs and opens the relevant System Settings pane. Calendar and Mirror both use it; Shortcuts does not need it.

---

## 5. Testing

Unit tested, pure: the clipboard store (dedupe, cap, pinning, exclusions, transient rejection, persistence round-trip), the pomodoro machine (every transition, phase progression, remaining-time boundaries, pause arithmetic), metrics derivation and formatting (byte rates, battery time, percentages, the missing first throughput sample), and the meeting-URL detector.

Behind protocols with fakes: `NSPasteboard`, the clock, IOKit and `host_statistics64`, EventKit, `AVCaptureSession`, and the `shortcuts` subprocess.

Not unit tested, verified by hand: camera preview, the AirDrop-style permission prompts, and every rendering.

---

## 6. Out of scope

- Notes and to-dos modules — NotchNook lists them as unshipped
- Weather — dropped in the parent spec
- Synthesising paste keystrokes
- Editing calendar events; the module is read-only
